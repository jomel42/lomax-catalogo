LOMAX - REPORTE E4
Etapa 4: Backend con API y endpoints

IMPLEMENTACION
Backend: Node.js y Express.
Imagen Docker: lomax-backend:1.0.
URL local: http://localhost:3000
Persistencia: RDS PostgreSQL y DynamoDB.
Imagenes: S3 y procesamiento sincrono mediante Lambda.

ENDPOINTS
GET /categorias
POST /productos
POST /productos/{id}/imagen
POST /productos/{id}/reprocesar
GET /productos
GET /productos/{id}
GET /productos/{id}/imagen

CONTRATO DE CARGA
POST /productos recibe JSON:
codigo, nombre, descripcion, precio, categoria_id y atributos.
POST /productos/{id}/imagen recibe multipart/form-data,
con un archivo en el campo imagen.
Formatos permitidos: JPEG y PNG.
Limite: 5000000 bytes.

PUBLICACION
El registro inicial queda PENDIENTE.
La publicacion requiere atributos validos, ejecucion correcta
de Lambda y verificacion de la miniatura recuperada de S3.
El reprocesamiento utiliza el original guardado.

ERRORES
400: entrada invalida.
404: producto o imagen no disponible.
409: codigo duplicado, original ausente o conflicto de procesamiento.
413: archivo superior al limite.
415: formato no permitido.
502/503: fallo de procesamiento o servicio dependiente.
La respuesta incluye error, paso y, cuando corresponde, producto_id.

PRUEBA CONTROLADA DE DEPENDENCIA
Se utilizo un contenedor temporal configurado con una funcion
Lambda inexistente. Se verifico la respuesta de error y la
conservacion del producto pendiente.
La recuperacion se realizo mediante el backend principal.
El contenedor temporal fue eliminado.

COMPARACION DE ARCHIVOS
La imagen descargada desde la API se comparo mediante SHA256
con el objeto descargado directamente de S3.

ALCANCE
Las imagenes utilizadas son archivos de prueba.
La carga de fotografias definitivas y la publicacion de al menos
20 productos forman parte de la continuacion del proyecto.
